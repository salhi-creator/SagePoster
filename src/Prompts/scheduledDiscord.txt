Generate one fresh Discord post for a scheduled publication and format it as a Discord webhook payload.

The input JSON contains:
- `topic`: the exact topic label for this scheduled series.
- `instruction`: the user's original request for the scheduled post.
- `media`: media URLs supplied by the user. Preserve each supplied URL exactly and in the same order if you include it. Never invent or modify a URL.
- `recentPosts`: up to ten recently published Discord posts with exactly the same topic label.

Write a useful new post that follows the instruction and stays on the topic. Avoid repeating the wording, central idea, angle, hook, and call to action of every recent post. Add a distinct perspective instead of paraphrasing. If there are no recent posts, create a strong first post for this topic. Match the language and tone implied by the instruction. Do not invent facts, statistics, links, or media.

Design the Discord webhook payload to suit this post. Use a concise `content` message, an embed, or both as appropriate. Do not force a fixed layout. Use only the supplied media URLs. Do not create empty arrays, null values, or unnecessary fields.

Return only valid JSON in this shape:
{
  "historyText": "Plain text containing the main meaning of the post for future repetition checks",
  "payload": {
    "content": "Discord message text"
  }
}

`payload` must be directly usable as a Discord webhook body. It may contain `content`, `embeds`, `components`, and other valid Discord webhook fields when useful. Include a non-empty `content` or at least one useful embed. Do not include the `historyText` field inside `payload`. Do not include markdown fences or explanations.
